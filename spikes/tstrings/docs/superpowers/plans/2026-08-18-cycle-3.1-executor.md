# Cycle 3.1: Execution Layer and Structured Outcome — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Add `Accepted`/`Rejection`/`InfrastructureFailure` to `types.py`, implement `run_candidate` (wrapper → executor → backwards JSON verdict parse) in `gate.py` with an injectable executor, and wire `satyrn-corpus-builder` as a path dependency.

**Architecture:** `run_candidate(code, checks, *, timeout=10, executor=None)` builds a wrapper program that runs `code`, evaluates each `Check` against captured stdout/values, and prints one JSON verdict as the last stdout line; the captured stdout is scanned backwards for the last parseable JSON object. The default executor is `satyrn.dataset.utils.sandbox.Sandbox`; tests inject a subprocess executor so no Docker is needed.

**Tech Stack:** Python 3.14, `ast`, `json`, `subprocess`, `satyrn.dataset.utils.sandbox` (new path dep), `pytest`, `ruff`.

**Spec:** `docs/superpowers/specs/2026-08-18-cycle-3.1-executor-design.md`

## Task 1: Types and the subprocess executor

**Files:** modify `types.py`, create `gate.py`, create `tests/test_gate.py`.

- [ ] **Step 1: Write the failing tests** — `tests/test_gate.py` imports `Accepted`, `Rejection`, `InfrastructureFailure`, `run_candidate`, `_subprocess_executor`, `Check`:

```python
def test_subprocess_executor_returns_stdout() -> None:
    assert _subprocess_executor("print('hi')", 10).strip() == "hi"


def test_known_good_accepted() -> None:
    code = 'x = t"Hello"\nprint("done")'
    checks = (Check(kind="uses_feature", expected="string.templatelib"),)
    outcome = run_candidate(code, checks, executor=_subprocess_executor)
    assert isinstance(outcome, Accepted)
```

(Also: a `Rejection(stage="semantic_check")` when `uses_feature` fails; `InfrastructureFailure` on timeout; `Rejection(stage="syntax")` on `x =`.)

- [ ] **Step 2: Run → FAIL** (`ImportError: cannot import name 'run_candidate'`).
- [ ] **Step 3: Implement** — add the three outcome dataclasses to `types.py`; add `gate.py` with `_subprocess_executor(program, timeout)` (runs `[sys.executable, "-c", program]`, `capture_output=True, text=True, timeout=timeout`, returns stdout; on `TimeoutExpired` returns `""`), and `run_candidate`:
  - Build the wrapper: **the candidate runs in a subprocess, never in-process.**
    `run_candidate` runs `code` once via the executor, capturing its stdout;
    evaluates each `Check` in the harness process (`expected_stdout` compares the
    captured stdout; `uses_feature` AST-inspects `code` for the required node);
    then serializes the verdict and appends it as the FINAL line of a combined
    stream `candidate_stdout + "\n" + json.dumps(verdict)`. `_parse_verdict`
    scans that combined stream backwards for the last line that `json.loads`.
    (This satisfies "scan stdout backwards for the last JSON object" — a
    candidate printing `{"x": 1}` mid-run cannot corrupt the verdict, because
    the verdict is the last JSON line.)
