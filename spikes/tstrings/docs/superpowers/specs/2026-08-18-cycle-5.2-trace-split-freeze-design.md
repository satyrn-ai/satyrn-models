# Cycle 5.2: Trace, lineage split, freeze corpus — design

## Purpose

Complete Phase 5 and the M1 milestone: fill each rendered row's `trace` with an
LLM-generated first-person reasoning paragraph (the sole LLM exception,
decision 3), split rows into train/valid on seed lineage, and freeze
`corpus-sft/{train,valid}.jsonl` + `manifest.json`.

## Context

- Roadmap M1, Phase 5 (final cycle). BRIEF Phase 5 (split + manifest), §2.1
  (the `trace` carve-out), Amendment 3.
- Prior: Cycle 5.1 (rendered rows, `trace=""`). `satyrn.dataset.llm` is
  importable (decision 4). Requires `DEEPSEEK_API_KEY` in the environment.

## Rulings (recommendations)

1. **Trace is reasoning prose about the deterministic code.** For each row,
   call `satyrn.dataset.llm` (DeepSeek) with a fixed prompt: "Write a short
   first-person reasoning trace explaining this Python program, its task, and
   step-by-step what it does, without mentioning training, datasets, or this
   prompt." The generated prose wraps the mined, gated, deduped code — it
   carries no API surface, so the 2.1 confabulation failure does not apply.
   **Determinism note:** the trace is the only non-deterministic field; the
   corpus `manifest.json` records the rendered fingerprint BEFORE trace so the
   deterministic content stays reproducible, and the trace fingerprint is
   recorded separately (informational).
2. **Split on seed lineage, whole-group — via a positional re-join.**
   `rendered.jsonl` carries only `filename` (converged schema, decision 2), so
   the true lineage unit (`provenance.path` + `provenance.line`, plus
   `semantic_id`) must be recovered by re-loading `tasks/gated.jsonl` and
   joining **positionally**: `render_tasks` is deterministic and 1:1
   order-preserving, so rendered row *i* corresponds to gated task *i*. Assign
   whole `(path, line)` groups to train or valid by a stable hash (target
   ~50/50 (8 of 16 hex digits)). Do NOT fall back to `filename` (that collapses 20 seed-groups to 5
   file-groups and yields a ~60/40 split). No seed's rows appear on both sides.
3. **Manifest records four fingerprints.** dataset (the deterministic rendered
   rows pre-trace), rendered (post-trace), benchmark (`ood-v2/tasks.jsonl`
   sha256), system prompt (`system-prompt.txt` sha256) + counts + the split
   rule. Counts must match actual line counts.
4. **Trace failure is honest.** If the LLM call fails for a row (network, key),
   stop and report — do not emit an empty/garbage trace silently.

## Components

- `render.py` additions — `generate_trace(row: dict, llm) -> str` (one LLM
  call per row, using `satyrn.dataset.llm`'s `Model`/`Context`).
- `split.py` — `lineage_split(rows: list[dict]) -> tuple[list[dict], list[dict]]`
  (whole-seed groups, stable hash, ~50/50 (8 of 16 hex digits)).
- `manifest.py` (or in `split.py`) — `write_manifest(...)` with counts + four
  fingerprints + split rule.
- CLI `freeze` command — `-i` rendered jsonl, `-o` output dir (default
  `corpus-sft`); generates traces, contamination is already passed, splits,
  writes `train.jsonl`/`valid.jsonl`/`manifest.json`.

## Testing

1. `lineage_split` keeps a seed's rows together (no seed spans both sides) and
   is deterministic.
2. `generate_trace` produces non-empty prose (mock the LLM in tests — no live
   key in CI).
3. `write_manifest` counts match actual line counts; four fingerprints present.
4. The CLI freeze run (with a mocked LLM) writes the three files.
5. A row's `trace` field is non-empty after freeze.
