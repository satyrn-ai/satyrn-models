# Cycle 10.1: Broaden sourcing to third-party repositories — design

## Purpose

Re-open the clean-room's "CPython only" scope to include the pinned
third-party repositories the prior iteration sourced (regex-template, t-sql,
tdom, storyville, tdom-svcs, pep750-examples), then re-run the corpus pipeline
over the larger pool. Clean-room rule holds: pin the repos, run **our** AST
miner — the prior hand-selected seed table is not carried forward.

## Rulings (recommendations)

1. **Per-source checkouts.** The `mine` CLI's single `-i` becomes a parent dir:
   each `input/<source_id>/` is a checkout of that source, verified against its
   own spec SHA and mined with `mine_seeds`. (The CPython checkout moves to
   `input/cpython/`.)
2. **Mine the whole repo** (`paths = ["."]`) for third-party sources — our AST
   walker finds *all* `TemplateStr` nodes, with no hand-selection bias (unlike
   the prior iteration's 24 hand-picked literals).
3. **Provision into gitignored `.cache/sources/<id>/`** (never committed), like
   the CPython checkout.
4. **Rebuild end-to-end** — mine → build → gate → dedup → render → freeze —
   and regenerate `datasets/tstrings-sft.jsonl` from the larger corpus.

## Components

- `sources.toml` — add the six third-party `[source_id]` entries (repo, commit,
  license `MIT`, `paths = ["."]`).
- `mine.py` — `main` resolves per-source checkouts: `input/<spec.id>/`.
- `.cache/sources/<id>/` — provisioned checkouts (gitignored).
- `seeds/mined.jsonl` — regenerated (CPython 23 + third-party seeds).

## Testing

1. `load_source_specs` parses all seven sources (cpython + six).
2. The `mine` CLI mines `input/<source_id>/` per source (a fixture dir tree).
3. Each third-party source yields non-empty seeds from its checkout.
