# Cycle 2.1: Seeds to tasks — design

## Purpose

Implement Phase 2 of the t-strings spike: deterministically turn the 23 mined
seeds into teachable `Task`s (`tasks/built.jsonl`), with per-cell floors set by
measurement, prompt-fingerprint diversity, and rejected candidates recorded
(`reports/dropped.jsonl`).

## Context

- Roadmap: `docs/superpowers/roadmap.md`, milestone M1, phase 2.
- Spec: `BRIEF.md`, Phase 2 (as amended 2026-08-18); §6 (data shapes); §2.1
  (no LLM — binding); §2.3 (record false directions); §5 (conventions).
- Prior: Cycle 1.1 landed `seeds/mined.jsonl` (23 seeds) and `types.py`
  (`SourceSpec`, `Seed`, `load_source_specs`).
- This cycle is fully deterministic (ground rule 2.1 reaffirmed for Phase 2
  in the 2026-08-18 brainstorm — see `docs/corpus-builder-convergence.md`,
  decision 6). The LLM `trace` is a Phase 5 render concern, not here.

## Rulings resolved in brainstorm (2026-08-18)

1. **No LLM (2.1 reaffirmed).** `build_tasks` never calls an LLM — no LLM for
   prompts, references, or checks. Deterministic transformation of mined seeds
   only.
2. **Measure-then-set floors (BRIEF amendment).** The "start at 15" rule is
   replaced by measurement: the first build counts real tasks per cell, then
   floors are written to `cells.toml` from those counts. Build fails naming a
   cell below its floor.
3. **`compose` dropped (BRIEF amendment).** Zero seeds demonstrate combining
   two Templates; a compose reference would be invented, not mined. Cells:
   construct, read_strings, read_values, read_interpolations, render,
   negative_control (6 cells).
4. **Derivation discipline.** One task per seed per *demonstrated* operation.
   No rote extension of every seed into every cell. Small (~50–100 task),
   construct-heavy corpus accepted (BRIEF §8/§9).

## Components

### `types.py` additions (BRIEF §6, defined once)

```python
@dataclass(frozen=True, kw_only=True)
class Provenance:
    source_id: str
    path: str
    line: int
    license: str

@dataclass(frozen=True, kw_only=True)
class Check:
    kind: str        # "expected_value" | "expected_stdout" | "uses_feature"
    expected: str    # for uses_feature, the required module or node name

@dataclass(frozen=True, kw_only=True)
class Task:
    prompt: str
    reference: str       # a complete, runnable program
    checks: tuple[Check, ...]
    role: str            # "author" | "consumer"
    operation: str       # key into cells.toml
    provenance: Provenance
    task_id: str         # sha256 over content INCLUDING provenance
    semantic_id: str     # sha256 over content EXCLUDING provenance
```

`task_id` hashes every field except itself and `semantic_id`; `semantic_id`
hashes the same fields minus `provenance`. Both are `sha256` over a canonical
JSON dump with sorted keys. Two tasks differing only in provenance share a
`semantic_id` and differ in `task_id`.

### Operation analysis (deterministic)

For each seed, AST-analyze `Seed.text` to decide which operations it
*demonstrates*:

- `construct` — contains ≥1 `ast.TemplateStr` (all 23 seeds).
- `render` — calls the `fstring()` test helper (the suite's template→f-string
  renderer) or walks `.strings`+`.values` together.
- `read_strings` — accesses `.strings`.
- `read_values` — accesses `.values`.
- `read_interpolations` — accesses `.interpolations`, `.conversion`, or
  `.format_spec`.
- `negative_control` candidate — the seed's dominant logic is f-strings /
  plain strings rather than t-string semantics (e.g. `test_type_repr`).

A seed demonstrating N operations yields up to N tasks (one per demonstrated
operation). Seeds that demonstrate none cleanly (e.g. the 3 annotation-context
seeds, where the t-string appears only in a type annotation) are dropped with
`reason` (ground rule 2.3).

### Reference derivation (deterministic, "faithful-lite")

Each task's `reference` is a complete, runnable program derived from the
seed's relevant statements:

1. Extract the statements exercising the target operation (for a render task,
   the t-string + the render call; for a construct task, the t-string literal).
2. Strip test scaffolding: remove `self.` prefixes, drop `assertX` wrappers.
3. Resolve test-suite helpers (`fstring`, `assertTStringEqual`) from the
   pinned source where they exist — `fstring(t)` is real code in
   `Lib/test/test_string/test_templatelib.py`; inline it deterministically so
   the reference is self-contained.
4. End with a `print()` of the observable value (for `expected_stdout`
   checks) or assign the value (for `expected_value` checks).

The reference must parse, run under Python 3.14, and its AST must contain a
`TemplateStr` (or `string.templatelib` reference) for every non-negative-
control task — that is the `uses_feature` check.

### Prompt families and fingerprints

≥6 prompt families — distinct phrasing templates slot-filled from the seed
(operation + its values/variable names). Families rotate across tasks so
wording does not correlate with operation (the prior "wording response"
failure). A prompt fingerprint is `sha256` of the normalized prompt (lowercase,
collapse whitespace, identifiers/literals drawn from the seed → placeholder).
Two prompts from the same family with different variable names produce the
same fingerprint. Acceptance: ≥35 distinct fingerprints total, ≥4 per occupied
cell.

### `negative_control` and the Phase 3 gate

negative_control tasks (from f-string-heavy seeds) are correctly solved
*without* t-strings. They carry `operation = "negative_control"` and:
- `reference` contains **no** `TemplateStr` (that is the property being
  taught) — verified by a check;
- Phase 3's `qualify` **skips** the anti-vacuity degenerate-proof for this
  operation and instead verifies: reference runs, produces expected output,
  and its AST contains no `TemplateStr`. (Defined here so the Phase 3 spec
  does not mis-gate negative_control as vacuous.)

### `reports/dropped.jsonl` (ground rule 2.3)

Rejected candidates written with a `reason` field, never silently dropped:
seeds that demonstrate no clean operation (annotation-context seeds), seeds
whose reference cannot be made self-contained, etc.

### Measure-then-set workflow

1. First build runs with provisional floors (`min_tasks = 0`), writes
   `reports/build.md` with per-cell counts.
2. Floors are written into `cells.toml` from the measured counts — generous
   where abundant (construct), honest where thin.
3. Final build enforces floors; acceptance fails naming any cell below its
   floor.

## Data flow

`seeds/mined.jsonl` + `cells.toml` → operation analysis → per-seed task
generation (prompt family + reference + checks + IDs) → `tasks/built.jsonl`
(+ `reports/build.md`, `reports/dropped.jsonl`).

## Error handling

- Seed that yields no task: recorded to `reports/dropped.jsonl` with reason —
  never a silent drop (2.3).
- Reference that cannot be made self-contained or does not parse: same —
  dropped with reason.
- Cell below its floor at final build: `click.ClickException` naming the cell.

## Testing (BRIEF Phase 2 acceptance, adapted to measurement)

1. Every cell in `cells.toml` meets its `min_tasks` floor (build fails naming
   the starved cell otherwise).
2. ≥35 distinct prompt fingerprints; ≥4 distinct fingerprints within every
   occupied cell.
3. `task_id` stable across runs for identical input.
4. Two tasks differing only in provenance share a `semantic_id` and differ in
   `task_id`.
5. Operation analysis: a fixture seed demonstrating two operations yields two
   tasks in the right cells; an annotation-only seed is dropped with reason.
6. Reference runnability: every reference parses and runs — in this cycle a
   lightweight subprocess with a timeout (the Phase 3 gVisor executor from
   `satyrn.dataset` replaces it at the gate); `uses_feature` holds for every
   non-negative-control reference.
7. negative_control references contain no `TemplateStr`.

Phase 2 splits into two cycles:

- **Cycle 2.1 — build mechanism** (this design): IDs, cells.toml, operation
  analysis, reference derivation, prompt families, fingerprints, dropped
  reporting; produces `tasks/built.jsonl` + `reports/build.md` with
  provisional floors.

  measured counts, enforce them, and land the full acceptance test suite.
