# Cycle 7.1: Preregister, train, evaluate, report — design

## Purpose

Complete Phase 7 and the M2 milestone: write the preregistration FIRST, add the
LoRA training command, wire the evaluate-all-arms + `REPORT.md` generation, and
document the live (environment-gated) training/evaluation procedure.

## Context

- Roadmap M2, Phase 7 (final phase). BRIEF Phase 7. Phase 6 harness (Cycle 6.1
  scorer + 6.2 generator) is the measurement instrument. `corpus-sft/train.jsonl`
  (16 rows) is the training data.
- Environment: Apple Silicon; `mlx-lm` pinned; `DEEPSEEK_API_KEY` unset (the
  trace in the corpus is mock); the Mellum2 Instruct base model is not cached.

## Rulings (recommendations)

1. **Preregistration content** (committed FIRST, before any training):
   - Hypothesis: fine-tuning Mellum2-Instruct on the t-strings corpus teaches
     t-strings beyond what documentation-in-context alone provides.
   - Arms: (a) bare base, (b) base + docs in context — **the comparator/bar**,
     (c) the trained LoRA adapters (5 seeds).
   - Metric: `summary.score` (correctness ∩ mechanism) from the Phase 6 harness.
   - Seeds: **5** (seeds 1–5).
   - Decision rule: **POSITIVE** iff the mean adapter `summary.score` exceeds
     the base+docs arm's `summary.score` measured by the same harness in the
     same run; otherwise **NEGATIVE**, reported plainly.
2. **The bar is our harness's base+docs score, not the historical 0.61.** The
   preregistration states this; `evaluate_arms` scores the docs arm and the
   adapters with the same instrument in the same run. (The 0.61 is a Phase 6
   reproduction target, not the Phase 7 bar.)
3. **Live training/evaluation is environment-gated.** The train/eval code is
   built and unit-tested with mocked mlx-lm; the live run (5 LoRA trainings +
   7 tiers of generation) is a documented procedure (`docs/training.md`). The
   acceptance "≥5 adapters exist" is satisfiable only by the live run.

## Components

- `PREREGISTRATION.md` — the frozen preregistration (committed first).
- `train.py` — the `train` click command: per seed, `mlx_lm.lora.train`
  (model, train data, seed, iters, output dir `adapters/seed<N>`).
- `eval.py` additions — `evaluate_arms(...)`: score bare base, base+docs, and
  each trained adapter with the Phase 6 harness; return per-arm `summary.score`.
- `report.py` (or `eval.py`) — `write_report(arms, preregistration)`: computes
  the adapter mean + spread, applies the decision rule, writes `REPORT.md`
  with a plain verdict line.
- `docs/training.md` — the documented live procedure.

## Testing

1. `train` command builds the correct `mlx_lm.lora.train` invocation per seed
   (mocked): model, data, seed, iters, output.
2. `evaluate_arms` scores all arms with the same harness (mocked generate +
   score) and returns per-arm `summary.score`.
3. `write_report`: a POSITIVE fixture (adapter mean > docs) → "decision rule
   met: POSITIVE"; a NEGATIVE fixture (adapter mean ≤ docs) → "NEGATIVE"
   plainly; mean and spread reported.
4. `PREREGISTRATION.md` exists and names hypothesis/arms/metric/seeds/rule.

## Out of scope

  (model download + hours of training + generation).

## Decomposition

One feature cycle (this). This closes M2; the whole effort is complete when the
live run lands `REPORT.md` with a decision-rule verdict (or reports negative).
