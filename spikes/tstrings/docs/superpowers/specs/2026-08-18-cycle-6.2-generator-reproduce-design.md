# Cycle 6.2: mlx-lm generator, three arms, reproduction — design

## Purpose

Add the generation side of Phase 6: `mlx-lm` (pinned), a `generate` function
supporting the three arms (bare base, base+docs, adapter), provision the
inherited `results/` and `adapters/`, and a `reproduce` command + documented
procedure that checks `summary.score` within ±0.03 of the reference targets.

## Context

- Roadmap M2, Phase 6 (second cycle). BRIEF Phase 6 (pins + reproduction
  targets). Cycle 6.1's scorer is the consumer.
- Environment: Apple Silicon (arm64); `mlx`/`mlx-lm` not yet installed; the
  Mellum2 Instruct base model is not cached (a `thinking` variant is); the
  inherited `results/` (2.3 MB) and `adapters/` (3.2 GB) live on
  `integration-tstrings-spike`.

## Rulings (recommendations)

1. **Pin everything the BRIEF pins.** `mlx-lm` at git commit
   `254d153fdeb6f150edd4fc5a54f9828638481fa8` (added as a path/git dependency);
   base model `jedisct1/Mellum2-12B-A2.5B-Instruct-mlx-8bit`; benchmark
   `benchmark/ood-v2/tasks.jsonl` (fingerprint `3a94d381…`); docs block
   `benchmark/pep750-docs-context-v3.md` (sha256 `582c42a688…`); `max_tokens 700`;
   greedy decode (temperature 0).
2. **Three arms = one `generate` with flags.** `generate(prompt, *, model,
   adapter_path: Path | None, docs: str | None, system_prompt: str) -> str`.
   bare base = `(None, None)`; base+docs = `(None, docs_block)`; adapter =
   `(adapter_path, None)`. Deployment system prompt from
   `benchmark/system-prompt.txt` (train/eval alignment, Cycle 5.1).
3. **Provision the inherited data.** `results/` (2.3 MB) is committed (copied
   from `integration-tstrings-spike` per BRIEF §3); `adapters/` (3.2 GB) is
   provisioned into a gitignored `.cache/adapters/` (like the CPython
   checkout) — never committed.
4. **The ±0.03 reproduction is a documented, environment-gated procedure, not a
   CI step.** It needs the base model downloaded + the adapters provisioned +
   ~700 generations on a 12B model. The `reproduce` command runs the harness
   over the three reference tiers and reports `summary.score` vs the targets
   (bare base 0.05, base+docs 0.61, any adapter 0.47–0.58), failing outside
   ±0.03. The unit-tested path (scorer + extraction) is Cycle 6.1.

## Components

- `eval.py` additions — `generate(...)` (mlx-lm), `reproduce(...)` (runs the
  three tiers, compares `summary.score` to the targets).
- `pyproject.toml` — `mlx-lm` pinned dependency.
- `results/*.json` (committed), `.cache/adapters/` (gitignored).
- `tests/test_eval.py` — a generator smoke test (mocked mlx-lm), a reproduce
  comparison test (mocked scores).

## Testing

1. `generate` builds the correct mlx-lm invocation for each arm (mocked mlx-lm).
2. `reproduce` compares `summary.score` to targets within ±0.03 (mocked scores:
   a within-tolerance set passes, an out-of-tolerance tier fails).
3. The reference result files load and `summary.score` matches the documented
   targets (0.05/0.61/0.47–0.58) — pins the comparator.

## Out of scope

- Phase 7 (preregistration, LoRA training, REPORT). The actual live
  reproduction run (model download + adapters + long generation).

## Decomposition

Cycle 6.2 = one feature cycle (this). Phase 7 follows.
