# Cycle 3.2: Anti-vacuity gate — design

## Purpose

Implement the gate that admits a task to the corpus only when a deliberately
degenerate solution has been **executed and observed to fail** (ground rule
2.2). This is the feature-usage proof: it rejects tasks a model could solve
without t-strings.

## Context

- Roadmap M1, Phase 3 (second cycle). BRIEF Phase 3 (the gate) + §2.2.
- Prior: Cycle 3.1 (execution layer + `Outcome`). Cycle 2.1's spec defined the
  negative_control rule this cycle implements.

## Rulings (recommendations)

1. **Five degenerate families, deterministic.** `f-string substitute`,
   `repr-as-render`, `static-join`, `conversion-omission`, `hardcoded-output`.
   Each is a function `degenerate_<name>(task) -> str` producing a candidate
   program that attempts the task **without** t-strings. The hardcoded-output
   family prints the expected answer — the output-equality check alone must be
   passable by it, which is the point.
2. **`negative_control` skips the degenerate proof.** A negative_control task
   is *supposed* to be solvable without t-strings; proving non-vacuity against
   it is meaningless. `qualify` for `operation == "negative_control"` verifies
   instead: the reference runs and returns `Accepted`, and its AST contains **no**
   `TemplateStr` (the property being taught). This is the rule Cycle 2.1's spec
   already documented.
3. **VacuityUntested is not a pass.** A degenerate that times out, returns
   `InfrastructureFailure`, or fails at a stage other than `semantic_check`
   yields `VacuityUntested` — recorded to `reports/dropped.jsonl` with reason,
   never silently passed.

## Components

### `gate.py` additions

```python
@dataclass(frozen=True, kw_only=True)
class Qualified:
    degenerates_run: int

@dataclass(frozen=True, kw_only=True)
class Vacuous:
    degenerate: str

@dataclass(frozen=True, kw_only=True)
class VacuityUntested:
    degenerate: str
    detail: str

Qualification = Qualified | Vacuous | VacuityUntested
```

- `qualify(task: Task, *, executor=None) -> Qualification`:
  1. `run_candidate(task.reference, task.checks)` must be `Accepted` — else
     the task is not known-good (reject with reason).
  2. For `negative_control`: verify the reference's AST contains no
     `TemplateStr`; return `Qualified(degenerates_run=0)`.
  3. Otherwise, for each degenerate family: build the degenerate, run it, and
     require `Rejection(stage="semantic_check")`. `Accepted` → `Vacuous`; any
     other non-semantic failure/timeout/infrastructure → `VacuityUntested`.
  4. All degenerates rejected at the semantic stage → `Qualified(n)`.
- `gate_tasks(tasks: list[Task]) -> tuple[list[Task], list[dict]]` — returns the
  qualified tasks and the drop records (`Vacuous` / `VacuityUntested` / not-
  known-good, each with `reason`), written to `reports/dropped.jsonl` (ground
  rule 2.3).
- CLI: a `gate` command (`-i` tasks jsonl, `-o` output-dir) that reads
  `tasks/built.jsonl`, qualifies, writes `tasks/gated.jsonl` + appends drops.

## Testing (BRIEF acceptance)

1. A known-good fixture task qualifies.
2. A fixture task solvable by f-string is rejected as `Vacuous`.
3. A fixture whose degenerate crashes at import returns `VacuityUntested`, not
   a pass.
4. A candidate printing `{"x": 1}` mid-run does not corrupt verdict parsing
   (regression from Cycle 3.1, re-asserted through `qualify`).
5. A negative_control task with no `TemplateStr` in its reference qualifies;
   one with a `TemplateStr` is rejected.

## Out of scope

- The real Docker run over all 57 tasks (manual, environment-gated) — the
