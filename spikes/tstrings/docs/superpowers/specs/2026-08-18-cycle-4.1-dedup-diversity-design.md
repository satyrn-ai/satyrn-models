# Cycle 4.1: Deduplicate, diversity floor, composition floor — design

## Purpose

Enforce the three anti-collapse guarantees on the gated tasks: dedup on
`semantic_id`, a distinct-skeleton diversity floor (measured, then enforced),
and a per-cell composition floor. Produces `reports/build.md` and
`reports/threshold-derivation.json`.

## Context

- Roadmap M1, Phase 4. BRIEF Phase 4 + §4 (measured failures: 0.037 skeleton
  collapse, composition imbalance, duplicate leakage).
- Prior: Cycle 3.2 (`tasks/gated.jsonl`). `semantic_id` already computed by
  Cycle 2.1 (content hash excluding provenance).

## Rulings (recommendations)

1. **Skeleton = normalized AST hash.** For each `task.reference`: `ast.parse`,
   rename every identifier to a placeholder (by first-seen order) and replace
   every literal value with a placeholder, then hash a canonical dump (or
   `ast.unparse`) of the normalized tree. Distinct skeletons / total tasks =
   the ratio. (A `NameError`/parse failure → the task is dropped with reason,
   consistent with build's honesty.)
2. **Floor is measure-then-set.** First build: record the measured ratio to
   `reports/threshold-derivation.json`; the floor is `max(0.25, 0.75 × measured)`.
   On this first build the floor is therefore at least 0.25 (conservative, per
   BRIEF). Acceptance: measured ratio ≥ the floor.
3. **Composition floor reads `cells.toml` `min_tasks`.** The same floors set in
   Cycle 2.2. `composition.py` reports per-cell counts and fails (naming the
   cell) if any cell falls below its floor. The build fails on a starved cell.
4. **Dedup is a no-op guard, not a fixer.** `deduplicate` returns tasks with
   zero duplicate `semantic_id`s (first occurrence wins); it must *report* any
   duplicates it removed (they indicate a build bug, not something to hide).

## Components

- `dedupe.py` — `deduplicate(tasks: list[Task]) -> list[Task]` keying on
  `semantic_id`; reports removed duplicates.
- `diversity.py` — `skeleton(reference: str) -> str` (normalized AST hash) and
  `distinct_skeleton_ratio(tasks) -> float`; `skeleton_floor(measured: float) -> float`.
- `composition.py` — `cell_counts(tasks) -> dict[tuple[str, str], int]` and
  `check_composition(tasks, floors) -> None` (raises naming a starved cell).
- `build.py` / CLI — a `postprocess` (or `check`) command that runs
  dedup → diversity → composition over `tasks/gated.jsonl` and writes
  `reports/build.md` (composition table + diversity counts) and
  `reports/threshold-derivation.json` (the measured ratio).

## Testing

1. `deduplicate` removes duplicate `semantic_id`s (fixture: two tasks differing
   only in provenance collapse; distinct content survives).
2. `skeleton` is identical for two references differing only in variable names
   and literal values; different for structurally different references.
3. `distinct_skeleton_ratio` computes the correct fraction on a small fixture.
4. `skeleton_floor(0.336) == max(0.25, 0.75*0.336)` (= 0.252); first-build floor ≥ 0.25.
5. `check_composition` raises naming a cell below its floor; passes when all met.
6. The real postprocess run writes `reports/build.md` + `reports/threshold-derivation.json`.

## Risk (measurement to watch)

The corpus is small (57 gated tasks, construct-heavy, with 3 near-identical
"construct empty Template" references). If the measured skeleton ratio is
below 0.25, the acceptance fails honestly — that is a real finding to surface
(either the derivation needs de-shaping in a future cycle, or the floor is
amended by measurement, as with the fingerprint floor). Record the number; do
not pre-adjust.
