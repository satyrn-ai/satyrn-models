# Cycle 6.1: Scorer and code extraction — design

## Purpose

Implement Phase 6's scorer: extract candidate code from a model completion,
then score it for **correctness** (the `name_equals` check, by executing both
candidate and reference) **and** **mechanism** (the `policy`: the AST contains a
`TemplateStr` and uses the required `templatelib_apis`). Reproduce
`summary.score` (passed/total) matching the reference result schema.

## Context

- Roadmap M2, Phase 6 (first cycle). BRIEF Phase 6 + §4 (measurement
  instability). Reference results at `results/eval-v2-*.json` (to be copied in
  Cycle 6.2; their schema is the reproduction target).

## Benchmark task schema (uniform — verified)

Every `benchmark/ood-v2/tasks.jsonl` row:
`checks = [{"kind": "name_equals", "name": <var>}]`,
`completion = {"mode": "complete_program"}`,
`policy = {"id": "tstring", "config": {"requires_template": true, "templatelib_apis": ["strings", "values"]}}`,
plus `prompt`, `reference`, `id`, `provenance`.

Reference result item schema (the reproduction target):
`{"candidate", "completion", "elapsed", "id", "passed", "prompt", "reason", "reference"}`;
`summary = {"failure_stages": {...}, "passed": N, "score": N/100, "total": 100}`.

## Rulings (recommendations)

1. **`passed` = extract AND parse AND correctness AND mechanism.** Failure is
   staged: `candidate_parse` (extraction/`ast.parse` failed), else `policy`
   (the correctness `name_equals` or the mechanism policy failed). This matches
   the reference `summary.failure_stages` shape (`{candidate_parse: 1, policy: 94}`).
2. **Correctness by execution.** Run the candidate and the reference in a
   subprocess (Cycle 3.1's `_subprocess_executor`), each wrapped to print
   `repr()` of the `name_equals` variable; compare the two values. A candidate
   that raises or does not define the variable fails.
3. **Mechanism by AST.** `requires_template` → the candidate's AST contains a
   `TemplateStr`; each `templatelib_apis` entry → the candidate accesses that
   `.attr` on a template (a `TemplateStr`-rooted attribute or a name that
   holds one). Missing → `reason="no t-string literal found where reference
   uses one"`-style message (exact wording is informative, not reproduced).
4. **Code extraction.** Take the first fenced code block (```, ```python, or
   bare ```), handling an unterminated final fence (take the rest); else the
   whole completion with leading/trailing prose stripped. Parse-failure →
   `candidate_parse`.

## Components

- `eval.py` — `extract_code(completion) -> str`; `score_completion(completion, task) -> dict`
  (returns `candidate`/`passed`/`reason`); `score_results(completions, tasks) -> dict`
  (the `summary` + per-task items, matching the reference schema); `load_reference_scores(paths) -> dict`.
- `tests/test_eval.py` — the four mandated scorer unit tests + extraction tests + a reference-schema round-trip test.

## Testing (BRIEF acceptance, first four are mandated)

1. correct + mechanism → `passed` true.
2. correct + no mechanism (no `TemplateStr`) → `passed` false, `policy` stage.
3. incorrect + mechanism → `passed` false.
4. unparseable completion → `passed` false, `candidate_parse` stage.
5. extraction: fenced block, unterminated final fence, prose-stripped whole.
6. `load_reference_scores` parses `eval-v2-base.json` → `summary.score == 0.05`.
