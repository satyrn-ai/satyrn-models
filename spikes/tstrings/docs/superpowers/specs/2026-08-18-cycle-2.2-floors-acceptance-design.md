# Cycle 2.2: Floors and acceptance — design

## Purpose

Formalize Phase 2 acceptance: write the real per-cell floors into `cells.toml`
from the measured build, fix the prompt-family grammar, apply three robustness
fixes, re-measure, and land the full acceptance test suite. This closes Phase 2
and unblocks Phase 3 (the anti-vacuity gate).

## Context

- Roadmap: M1, phase 2 (final cycle). BRIEF Phase 2 (as amended 2026-08-18).
- Prior: Cycle 2.1 merged — `tasks/built.jsonl` (57 tasks, 6 cells,
  26 distinct fingerprints, 7 drops). `cells.toml` floors are provisional 0.
- Measured per-cell counts (the floor inputs): construct 21, render 10,
  read_strings 11, read_values 11, read_interpolations 3, negative_control 1.

## Rulings (approved 2026-08-18)

1. **Floors = exact measured counts** (re-measured after the fixes below).
   A floor is a regression guard: the build fails naming any cell that falls
   below its measured yield. No margins, no guessing — consistent with the
   measure-then-set ruling from the Phase 2 brainstorm.
2. **Prompt grammar fix = reword the family templates to fit bare
   infinitives.** `create`, `show`, `output` currently produce broken English
   ("that build a Template", "by build a Template"). Reword to the infinitive
   form ("Write a Python program **to** build a Template") rather than
   conjugating verbs per family. Then re-measure fingerprints and update the
   BRIEF amendment number (currently 26) to the new measured count.
3. **Robustness fixes in scope:** per-cell family rotation (guarantee ≥4
   distinct families per cell with ≥4 tasks *by construction*, not by ordering
   luck); return-annotation detection (`def f() -> t"{a}"` must drop, like
   parameter annotations); preceding-only assignment scoping (a name assigned
   *after* the literal is not carried as a binding).
4. **Enforcement:** the `build` command fails (`click.ClickException`) naming
   any cell below its floor; a test runs the real build asserting all floors
   met and distinct fingerprints ≥ the re-measured floor.

## Components

### `cells.toml`

Final `min_tasks` per cell, written from the re-measured counts (expected:
construct 21, render 10, read_strings 11, read_values 11, read_interpolations
3, negative_control 1 — re-verify after the code fixes).

### `build.py`

- **Prompt-family reword** — `create`/`show`/`output` templates changed to
  infinitive form (e.g. `"Write a Python program to {op}. Print the result."`).
  The `(family, operation)` fingerprint space is unchanged in structure; only
  the wording changes.
- **Per-cell family rotation** — replace the global `idx % 6` rotation with a
  per-cell rotation (reset per `(role, operation)`) so any cell with ≥4 tasks
  is guaranteed ≥4 distinct families regardless of seed ordering.
- **Preceding-only assignments** — `_collect_simple_assignments` scopes to
  assignments that lexically precede the literal (source order), matching the
  spec's "preceding simple assignment" rule.

### `cells.py`

- `_in_annotation_context` also returns true when the `TemplateStr` sits in a
  function's return annotation (`ast.FunctionDef`/`ast.AsyncFunctionDef`
  `.returns`), in addition to `ast.arg`/`ast.AnnAssign`.

### Tests (all in the existing test files; 38 existing must stay green)

1. **Floor enforcement** — run the real `build_tasks` over the 23 seeds
   (or a fixture) and assert every cell ≥ its `cells.toml` floor.
2. **Fingerprint floor** — distinct fingerprints ≥ the re-measured floor.
3. **Grammar** — assert no prompt contains the broken patterns
   (`"Templateing"`, `"that build a"`, `"by build a"`).
4. **Per-cell rotation** — a synthetic seed set where global rotation would
   under-serve a cell must still yield ≥4 distinct families in that cell.
5. **Return annotation** — `operations_of('def f() -> t"{a}": pass')` → empty.
6. **Preceding scope** — a name assigned after the literal is not carried
   into the reference (the literal is dropped with reason, not silently
   resolved from a later assignment).

### BRIEF

Update the fingerprint-amendment number (26 → re-measured) in the Phase 2
acceptance text after the re-measurement.

## Measure-then-set workflow (final)

1. Apply the code fixes (grammar, rotation, return-annotation, preceding
   scope) + their unit tests.
2. Run the real build on the 23 seeds.
3. Re-measure per-cell counts + distinct fingerprints.
4. Write the floors into `cells.toml` from the measured counts.
5. Run the build again — acceptance: every cell ≥ its floor; distinct
   fingerprints ≥ the re-measured floor; ≥4 families per ≥4-task cell (now by
   construction).
6. Update the BRIEF amendment number.
7. Commit: `cells.toml` floors + code + tests + updated outputs (`built.jsonl`,
   `build.md`, `dropped.jsonl`) + BRIEF.

## Acceptance (Phase 2 formally green)

- Every cell in `cells.toml` meets its `min_tasks` floor (build fails naming
  the cell).
- Distinct fingerprints ≥ the re-measured floor (≥26 expected; wording change
  should not reduce the `(family, operation)` space).
- ≥4 distinct families per cell with ≥4 tasks (by construction).
- `task_id` stable across runs; `semantic_id`/`task_id` relation holds
  (already green, re-verified).
- Full suite green (38 existing + the new tests).
