# Cycle 0.1: Package skeleton

## Purpose

Establish the installable package surface for the t-strings spike: a Click CLI
group with six real stub subcommands, each in its own module, matching the
repo's existing convention. Later cycles fill the stubs with real behavior; this
cycle makes the package installable, lint-clean, and verifiable by `pytest`.

## Context

- Roadmap: `spikes/tstrings/docs/superpowers/roadmap.md`, milestone M1, phase 0.
- Spec: `spikes/tstrings/BRIEF.md`, section 5 (conventions), section 6
  (architecture), Phase 0.
- Convention reference: `corpus_builder/src/satyrn/dataset/cli.py` and
  `corpus_builder/src/satyrn/dataset/sft.py` (Michał Karzyński's structure).
- Lint: repo-root `ruff.toml` governs (line-length 120; rules include `B`, `C4`,
  `E`, `F`, `G`, `I`, `PTH`, `RUF`, `SIM`, `UP`).

## Architecture

`src/`-layout installable package `satyrn.tstrings` at `spikes/tstrings/`. One
Click group with six real stub subcommands, each in its own module — mirroring
`corpus_builder`'s structure where `cli.py` registers stage modules exposing
`main`. Everything through `render` runs on CPU; training/eval stubs do not
execute anything yet.

## Components

### `spikes/tstrings/pyproject.toml`

- Build backend `hatchling`.
- `requires-python = ">=3.14"` (the spike uses `ast.TemplateStr` in Phase 1,
  which is 3.14-only).
- `dependencies = ["click"]`.
- `spikes/tstrings/.python-version` = `3.14` — pins the interpreter
  spike-locally, matching the `spikes/pep750/.python-version` precedent; the
  repo-root `.python-version` stays 3.13 (the trainer pins `<3.14`).
- `[dependency-groups] dev = ["pytest>=9,<10", "ruff==0.16.2"]` — pins match
  `corpus_builder` exactly (BRIEF amendment 5). The mechanism stays uv's
  `[dependency-groups]` rather than `[project.optional-dependencies]` because
  the BRIEF's Phase 0 acceptance command is plain `uv sync`, which does not
  install extras by default (verified empirically). No `spike` group with
  `mlx-lm` in this cycle — that is an M2 concern
  (Phase 6 pins `mlx-lm` to a specific commit; see BRIEF section 7, Phase 6).
- `[project.scripts] satyrn-tstrings = "satyrn.tstrings.cli:cli"`.
- `[tool.hatch.build.targets.wheel] packages = ["src/satyrn"]`.
- `[tool.pytest.ini_options] testpaths = ["tests"]` and `pythonpath = ["."]`
  — matches the prior spike pyproject, so `pytest` finds tests and resolves
  imports without extra config.
- No `[tool.ruff]` block — the repo-root `ruff.toml` governs (BRIEF §5). A
  local `[tool.ruff]` would shadow the root config and drop the `G`/`PTH`
  rules the BRIEF relies on; see the plan's spec-deviation note.

### `src/satyrn/tstrings/__init__.py`

Empty package marker.

### `src/satyrn/tstrings/cli.py`

Defines `@click.group("satyrn-tstrings")` with a one-line docstring. Imports
each stage module's `main` and `cli.add_command(...)`s all six. Thin file, no
command bodies. Structure mirrors `corpus_builder/src/satyrn/dataset/cli.py`.

### `src/satyrn/tstrings/{mine,build,gate,render,train,eval}.py`

Six stage modules. Each defines a `@click.command("<name>")` stub with:

- a one-line imperative docstring,
- standard `-i/--input` and `-o/--output-dir` options
  (`click.Path(path_type=Path)`, neither required yet),
- a body of `raise click.ClickException("<name> is not yet implemented")`.

Matches the stub convention in
`corpus_builder/src/satyrn/dataset/sft.py` exactly.

### `tests/test_cli.py`

Click `CliRunner` smoke test. Invokes `satyrn-tstrings --help`, asserts:

- exit code 0,
- all six subcommand names (`mine`, `build`, `gate`, `render`, `train`,
  `eval`) appear in output.

No fingerprint test — that belongs to Cycle 0.2 (frozen benchmark inheritance).

## Data flow

None yet. The CLI parses options and refuses. This cycle establishes the
installable surface that later cycles fill.

## Error handling

User-facing failures raise `click.ClickException` (the stubs do this). No
library functions yet, so no built-in-raising library errors. Every public
function carries a one-line imperative docstring (BRIEF convention).

## Testing

`tests/test_cli.py` via Click's `CliRunner` is the sole assertion that the
skeleton works. Log calls use printf style (`logger.info("... %s", value)`),
never f-strings (enforced by the `G` ruff rule). Paths via `pathlib`, never
`os.path` (enforced by the `PTH` rule).

## Acceptance (Phase 0 subset for this cycle)

- `uv sync` succeeds.
- `ruff check .` clean against repo-root `ruff.toml`.
- `satyrn-tstrings --help` exits 0 (verified by `tests/test_cli.py`).
- `pytest` passes with the CLI smoke test green.

The fingerprint test and ood-v2 file copy are Cycle 0.2.
